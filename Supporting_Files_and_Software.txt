================================================================================
  SECTION 1 — PROJECT OVERVIEW
================================================================================

  What is this project?

  This is an AI-powered web application that helps users figure out the best
  career path for themselves. A user can upload their resume (PDF or Word file),
  and the system will:

    - Read and understand the resume using AI
    - Find the best matching job roles for that person
    - Show a skill gap — what skills the user is missing
    - Generate a personalised learning roadmap
    - Provide career advice powered by Google Gemini AI
    - Show job market trends and intelligence

  In simple words: Upload your resume → Get career advice → Know what to learn.

  SECTION 5 — ENVIRONMENT & CONFIGURATION FILES
================================================================================

  These files store all the secret keys and settings. NEVER upload these to
  GitHub. They are listed in .gitignore for security.

  ── /ai/.env ──────────────────────────────────────────────────────────────────

    GEMINI_API_KEY=your_google_gemini_api_key
    OPENAI_API_KEY=your_openai_api_key
    MONGO_URI=your_mongodb_connection_string
    PORT=5000

  ── /backend/.env ─────────────────────────────────────────────────────────────

    MONGO_URI=your_mongodb_connection_string
    JWT_SECRET=your_jwt_secret_key
    AI_SERVICE_URL=http://localhost:5000
    PORT=8000
    GEMINI_API_KEY=your_google_gemini_api_key

  ── /front (no .env needed locally) ──────────────────────────────────────────

    The frontend uses a proxy setting in package.json that automatically
    points API calls to http://localhost:8000 (the backend).

  HOW TO GET API KEYS:

    → OpenAI API         : https://platform.openai.com/api-keys    (Paid)

================================================================================
  SECTION 8 — HOW TO RUN THE PROJECT (STEP BY STEP)
================================================================================

  OPTION A: Run All at Once (Windows Only — Easiest Way)
  ──────────────────────────────────────────────────────
    Just double-click the file: start_all.bat
    This starts all 3 services automatically.

  OPTION B: Run Each Service Manually
  ─────────────────────────────────────

  STEP 1 — Start the AI Service (Python)
  ----------------------------------------
    Open Terminal 1:
      cd ai
      pip install -r requirements.txt     ← (only first time)
      python app.py

    ✅ AI Service is now running at: http://localhost:5000

  STEP 2 — Start the Backend (Node.js)
  --------------------------------------
    Open Terminal 2:
      cd backend
      npm install                          ← (only first time)
      npm run dev

    ✅ Backend is now running at: http://localhost:8000

  STEP 3 — Start the Frontend (React)
  -------------------------------------
    Open Terminal 3:
      cd front
      npm install                          ← (only first time)
      npm start

    ✅ Frontend is now running at: http://localhost:3000

  Open your browser and go to: http://localhost:3000

  SECTION 12 — SECURITY PRACTICES USED IN THIS PROJECT
================================================================================

  This project follows industry-standard security practices to protect user
  data and credentials. Below is a clear list of every security measure used.

  1. SECRET KEYS IN .env FILES (Never Hardcoded)
  ─────────────────────────────────────────────────
  All sensitive information (API keys, database passwords, JWT secrets) are
  stored in .env files. They are never written directly inside the code.
  If someone reads the source code, they will not find any real keys.

  2. .gitignore — BLOCKS SECRETS FROM GITHUB
  ─────────────────────────────────────────────
  The .gitignore file is configured to block all .env files from being
  accidentally pushed to GitHub. Only .env.example files (with placeholder
  values) are shared — never real credentials.

  3. JWT (JSON Web Tokens) — SECURE LOGIN
  ──────────────────────────────────────────
  When a user logs in, the system gives them a JWT token (a digitally signed
  code). Every protected page/API requires this token. Tokens expire
  automatically, reducing the risk of misuse.

  4. PASSWORDS NEVER STORED AS PLAIN TEXT
  ──────────────────────────────────────────
  User passwords are hashed (scrambled using a one-way algorithm) before
  being stored in the database. Even if someone accessed the database,
  they cannot read the actual passwords.

  5. CORS — CONTROLS WHO CAN ACCESS THE BACKEND
  ─────────────────────────────────────────────────
  CORS (Cross-Origin Resource Sharing) is configured so that only the
  frontend (trusted origin) can make requests to the backend. Requests
  from unknown or untrusted websites are automatically blocked.

  6. MULTER — FILE UPLOAD VALIDATION
  ─────────────────────────────────────
  The file upload system (Multer) only accepts PDF and Word (.docx) files.
  Any other file type is rejected before it reaches the server.

  7. ENVIRONMENT SEPARATION
  ──────────────────────────
  The project has separate configurations for development (local) and
  production (deployed). Production keys are stored in the cloud
  deployment dashboard — never in the code repository.

  Files that are SAFE to share (no real secrets inside):

    ✓  All source code files (.js, .py, .jsx)
    ✓  This document

  Files that are NEVER shared:
